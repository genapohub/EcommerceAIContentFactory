## 摘要

**已核实三套国内官方 API 方案：阿里云百炼万相、火山方舟 Seedream/Seedance、可灵官方 API。建议万相作为第一轮成本基线，Seedream/Seedance 作为多图参考与视频编辑对照，可灵作为人物动作与原片编辑对照。** 三者均查到具体请求接口和输入参数，结论不依赖营销演示。Vidu 仅补充与视频复刻直接相关的公开接口证据。

**当前产品尚未接入模型。** 页面提交执行 `ContentEngine.generatePlan(data)`，生成本地内容计划并渲染、保存记录；不能将页面预览、配置草案、模拟检测描述成真实模型生成。本报告中的供应商、任务编排、成本统计、素材合成均为未来建议。

**爆款视频复刻应定义为：视频理解 + 拆镜头 + 商品参考 + 镜头生成 + 合成。** 原生 video-to-video 是其中一种镜头处理能力，不能自动代替商品事实核对、脚本改写、字幕排版、音轨处理和整片验收。即使供应商提供“一键复刻”API，也不能仅由接口名称推断底层就是单模型 video-to-video。

| 优先级 | 未来方案 | 已核实能力 | 主要取舍 |
| --- | --- | --- | --- |
| 第一轮基线 | 万相 2.6 文生图/图像编辑 + 2.6 i2v-flash；按需用 2.7 参考/编辑和 2.2 动作 | 文生图、图生图、图生视频、视频参考、视频编辑、动作迁移 | 普通无声图生视频 720P 为 0.15 元/输出秒；参考/编辑必须另算输入视频费用 |
| 能力对照 | Seedream 4.5 + Seedance 2.0 mini；复杂编辑评估 Seedance 2.5 | 多图生图、图生视频、全模态参考、视频编辑/延长 | 视频按 token 计费，有参考视频时存在最低用量；真人素材有额外接入限制 |
| 动作对照 | Kling Image 3.0 + Kling 2.6 + Kling O1 | 文生图、图生图、图生视频、特征视频参考、原片编辑、动作控制 | 官方有新旧协议，必须成套使用；动作控制适合人物连续动作，不是通用商品运动复刻 |

国内配置仅考虑上述国内服务商。**Topview 及国外模型只可作为竞品参考，不进入服务商列表、默认路由、备用模型或预算配置。** 不把“即梦消费端有功能”直接等同于“火山方舟 API 可调用”。

## 二、能力定义：避免把所有视频输入都叫复刻

| 能力 | 核心输入 | 能证明什么 | 不能据此承诺什么 |
| --- | --- | --- | --- |
| 文生图 | 文本 | 从描述生成图片 | 商品包装、Logo、规格与实物必然相同 |
| 图生图/图像编辑 | 商品图 + 指令 | 可参考或编辑图像 | 像素级不变、所有角度结构不变 |
| 图生视频 | 首帧或首尾帧 + 文本 | 围绕给定画面生成运动 | 复现另一条视频的动作和全部分镜 |
| 参考视频生成 | 视频 + 图片/文本 | 将视频的主体、音色、风格或动态用于新生成；具体语义看参数 | 一定保留原片时间轴、背景、运镜或动作 |
| 原片视频编辑 | 明确的待编辑视频 + 修改指令/参考图 | 对输入视频执行编辑，是本文所说的原生视频编辑接口 | 任意长视频一键无损换商品、底层模型结构已公开 |
| 动作迁移 | 人物图 + 动作视频 | 把人物动作驱动到目标人物 | 适用于所有瓶罐、食品、器械的物理运动 |
| 爆款结构复刻 | 授权参考片 + 商品资料 + 制作规则 | 在产品侧重建开头钩子、镜头顺序、卖点节奏与成片 | 原样抄片、一致性零漂移、转化率必然提升 |

“原生”在本文仅指 API 明确接受视频并提供视频编辑/条件生成能力，**不声称供应商内部只运行一个模型，也不声称没有工作流**。

### 3.2 接入判断

适合先验证“实拍商品图生成场景图，再生成 3 个短镜头”的主链路。普通 i2v、参考 r2v、视频编辑、动作迁移应分为四种任务，不能只给一个“视频模型”字段。

异步视频请求需 `X-DashScope-Async: enable`，创建后持久化 `task_id`，通过 `GET /api/v1/tasks/{task_id}` 查询。文档给出的任务和结果链接有效期为 24 小时；取得结果后转存自有对象存储。查询 RPS 20 是文档给出的查询限制，**不是模型生成并发数**。[A3][A5][A6]

未核实：本账号各模型是否开通、生成并发、实际耗时分布、商品文字保真率、输入多视频计费的逐段汇总/取整细则。估算时保留供应商账单用量字段，不自行猜测取整方式。

| Kling 2.6 动作控制 | 是。[C4] `POST /motion-control/kling-2.6` | “生成视频中的人物动作与参考视频一致”；“积分扣减计算以输出视频时长为准” | `contents` 含 `image`+`video`；视频 3~30 秒、≤100MB，宽高 340~3850；`character_orientation=image` 最长10秒，`video` 最长30秒；建议单人、一镜到底 | 720P 0.50 元/输出秒，1080P 0.80。[C5] |

### 5.2 不能混用的条件

动作控制文档提示：动作过快或难度过高，可能只提取出部分有效连续动作，结果会短于输入视频。多镜头快剪应先拆成单镜头，不能把整条爆款视频直接当动作素材。[C4]

官方价格资源中的图像积分与视频积分显示不同人民币对应关系：例如图像“8积分（¥0.2）/张”、视频“0.3积分（¥0.3）/秒”。**不建立跨能力统一的‘1积分=多少钱’常量**，按产品/模型/规格价目表核算。[C5][C6]

API 已公开不等于本账号的所有模型均开放。实际套餐、最低购买门槛、生成并发、具体凭证签发方式和完整失败扣费规则未核实；本次只确认文档要求 `Authorization`，未验证任何凭证。新视频公共查询结构与旧图片结构不同，也不应共用未经转换的响应解析器。

## 七、选型比较与未来架构

### 7.1 三方案比较

以下为**架构接入优先级评分**，1~5分，5为有利；不代表生成质量排行榜。权重参考角色方法，提高文档、落地成本和学习成本权重，降低扩展性权重。团队实操熟悉度未知，暂以接口数量、协议差异和开通约束估计学习成本，不能当成团队经验实测。

| 维度 | 权重 | A 万相 | B Seedream/Seedance | C 可灵 |
| --- | --- | --- | --- | --- |
| 电商所需 API 覆盖与任务控制 | 30% | 4 | 5 | 5 |
| 官方契约与证据可追溯性 | 25% | 5 | 4 | 4 |
| 验证成本与计费可预测性 | 20% | 5 | 3 | 3 |
| 学习/开通与运维复杂度 | 15% | 4 | 3 | 3 |
| 可替换性/扩展性 | 10% | 4 | 4 | 3 |
| 加权分 | 100% | **4.45** | **3.95** | **3.85** |

A 的优势是普通图片、i2v和动作的价格口径直接；B 的优势是多图参考和显式编辑任务类型，代价是真人流程和token预算；C 的优势是独立动作控制和 `base_video/feature_video` 区分，代价是新旧协议及积分口径转换。三者的真实画质、速度和一致性本次一律不评分。

### 7.2 爆款结构复刻的数据流

```mermaid
flowchart LR
    A[授权参考视频与商品实拍] --> B[抽帧与音轨提取]
    B --> C[视频理解 OCR ASR]
    C --> D[镜头清单与商品事实核对]
    D --> E[商品参考图与分镜首帧]
    E --> F[图生视频或原片编辑]
    F --> G[一致性检查与镜头筛选]
    G --> H[剪辑 字幕 配音 合成]
    H --> I[成片验收与成本回写]
```

1. **理解**：视频文件或抽帧交给国内视觉理解服务，提取开头钩子、卖点顺序、人物行为、镜头切换与字幕。百炼视觉理解文档已明确支持视频文件和帧列表，示例含 `video_url`，可输出时间戳事件。[A9] 音轨 ASR 单独核验，不因视觉模型接受视频就假定其已准确识别语音。
2. **拆镜头**：用场景切分和人工校对得到 `shot_id/start/end/景别/运镜/动作/字幕/音轨/卖点`。模型时间戳只是候选，不能替代帧级检查。
3. **商品参考**：每个 SKU 固定正面、侧面、细节图与事实表；用图生图制作新分镜。Logo、包装文字、尺寸和颜色设为保真项。不要让文生图凭名称猜商品。
4. **生成**：默认用商品首帧做 i2v；需要保留原片结构时单独评估编辑；人物舞蹈用动作迁移。供应商单段时长和输入限制决定拆分边界。
5. **合成**：通过未来后端的 FFmpeg 等工具完成镜头拼接、裁切、字幕、配音、BGM与封面；字符和价格优先后期叠加，避免生成模型改写关键信息。

例如一条15秒收纳用品参考片，0~3秒痛点、3~8秒演示、8~12秒对比、12~15秒卖点收尾。复刻目标是用自己的商品重建这套结构；不要求编辑模型一次吃下整片，更不以换掉画面中一个主体等同于完成广告成片。

### 7.3 未来接入契约建议

| 模块 | 未来必须具备的行为 | 验收依据 |
| --- | --- | --- |
| 国内配置 | 按服务商、地域、模型版本、能力配置；区分理解、生图、图生视频、参考、编辑、动作 | Topview与国外模型不出现在可执行配置；未知能力默认关闭 |
| 后端凭证 | 服务端托管，仅返回配置是否就绪；前端不持有可调用密钥 | 日志、浏览器存储、报告、错误提示中不出现凭证 |
| 任务编排 | 创建、排队、运行、成功、失败、取消、未知/超时；保存上游任务ID | 超时先查询，不能直接重提造成重复付费；重试单独记成本 |

### 8.3 指标、预算与止损

- 图片/镜头评分：商品一致性40分、结构与动作25分、画面可用性20分、卖点与分镜契合15分；双人盲评，分差>15分复核。**≥80分且无P0才算可用**。
- P0：变成另一SKU、改Logo/规格/关键文字、虚构功能或价格、严重商品变形、不可接受肢体错误。最终选用素材要求P0=0；候选中的P0必须如实计入淘汰率。
- 第一轮目标：技术成功率≥95%；候选可用率≥70%；每方案至少8/10个SKU能在固定候选预算内产出合格成片。10 SKU只用于筛掉明显不适合的方案，不能宣称具备统计显著的全面优胜。
- 记录：排队时间、生成时间、端到端P50/P95、失败原因、审核拒绝、人工修整分钟数、单合格图片/单合格15秒成片成本；速度目标暂设单条成片P95≤20分钟，作为验证目标而非供应商SLA。
- 预算：本轮建议人民币600元**验证上限**，不是已发生费用；供应商充值沉淀资金另列。开始付费前必须补齐价目和用量规则；单镜头最多2个候选，技术失败重试最多1次且占预留预算，不无限抽卡。
- 缺少凭证、开通条件或可核算价格时，相应单元标记“未执行”，不能以本地计划或模拟素材代替模型验收。本次全部模型验证单元均为未执行。

## 九、成本公式与可复算预算

### 9.1 通用成本模型

```text
图片成本 = Σ(成功输出张数 × 输出单价 + 应收费输入张数 × 输入单价)
普通视频成本 = Σ(账单认可的输出秒数 × 对应模型/分辨率/声音单价)
参考/编辑成本 = Σ(该模型规定的输入计费量 + 输出计费量) × 对应单价
token视频成本 = Σ(实际 usage.completion_tokens / 1,000,000 × 每百万token价格)
积分成本 = Σ(任务实际扣减积分 × 该能力对应人民币换算/套餐折扣)
全部成本 = 理解/OCR/ASR + 图片 + 所有视频候选 + 编辑/动作专项
         + 配音/音乐授权 + 合成算力 + 存储流量 + 人工审核与修整
单合格成片成本 = 全部成本 / 验收合格成片数
```

技术成功但商品不合格的生成仍会产生费用；供应商的“失败不收费”通常不包括主观画质不满意。优惠额度只能降低现金支出，不从模型经济成本中抹除。并发购买、充值余额与实际调用消耗分账记录。

### 9.2 三方案基准预算

统一每方案60张图、60段5秒720P无声视频，共300输出秒。仅估算上述生成环节，未含专项、理解与合成，也不是15秒成片的最终交付报价。

| 方案 | 图片 | 普通i2v | 小计 |
| --- | --- | --- | --- |
| A 万相2.6 | 60×0.20=12.00元 | 300×0.15=45.00元；显式 `audio=false` | **57.00元** |
| B Seedream4.5 + Seedance2.0 mini，刊例 | 60×0.25=15.00元 | 300×720×1280×24÷1024÷1,000,000×23=149.04元 | **164.04元** |
| B 同上，本期4折视频价 | 15.00元 | 149.04×0.4=59.616元 | **74.62元** |
| C Kling Image3.0 + Kling2.6 | 60×0.20=12.00元 | 300×0.30=90.00元 | **102.00元** |

三方案合计：刊例 **323.04元**；在mini活动有效且账号实际适用时约 **233.62元**。B使用官方token估算公式和720×1280、24fps假设，最终以API usage为准，不能将表中金额当成固定报价。[A7][B3][C5][C6]

### 9.3 专项预算与易漏成本

| 场景 | 计算方法 / 示例 | 注意事项 |
| --- | --- | --- |
| 万相2.7参考，单输入片 | `(min(输入计费秒数,5)+输出秒数)×单价`；10秒参考+5秒输出、720P约6元 | 多输入片的汇总/取整本次未核实；不要把视频文件长度上限30秒当计费上限 |
| 万相2.7编辑 | `(输入秒数+输出秒数)×单价`；5秒入+5秒出、720P=6元 | 3个编辑专项约18元；不能只算输出的3元 |
| Seedance2.5编辑 | `max(估算token,该规格最低token)×42/百万`，720P有视频输入 | 估算token=`(输入秒数+输出秒数)×宽×高×帧率÷1024`；最低量需按规格核实，专项暂不伪报精确金额 |
| Kling O1编辑 | 有视频720P刊例0.90元/秒；最终以该任务扣费契约和账单为准 | 输入另计/取整未核实，不把“5秒×0.9”当全部确定成本 |
| 万相动作标准 | 2段×5秒×0.40=4元 | 按成功输出时长 |
| Kling2.6动作720P | 2段×5秒×0.50=5元 | 有效动作提取可能缩短输出，按账单输出时长 |
| Vidu复刻（另行评估） | `复刻计费秒数×16积分×0.03125`，720P即0.50元/计费秒 | 输入还是输出作为计费时长未核实；不能直接宣称15秒原片固定7.5元 |

600元上限包含对上述不确定专项和基础服务的预留，不代表所有未知价格已被核实。只要预估与预留余额不能覆盖下一任务，就应停止自动提交。用一张漂亮样片的费用推算批量生产成本会漏掉落选候选、重试和人工修整。

## 十、决策记录与未核实事项

### ADR-001：以三家国内官方 API 建立验证基线

- 状态：研究建议，2026-09-17；未实施。
- 背景：现有页面只生成本地计划，需要核实真实生成路径、供应商限制和单位成本。
- 决策：先按A/B/C完成固定样本对照；首个接入倾向A，保留B的多参考编辑与C的动作专项。外部竞品不进入国内配置。
- 理由：三家均取得接口级证据，能按不同能力配置和独立核算；避免未经验证直接绑定一家的全部工作流。
- 后果：需要实现任务归一化与供应商适配；生成质量和实际单位可用成本必须等10 SKU结果再定最终路由。

### ADR-002：复刻由可检查的分镜工作流交付

- 状态：研究建议，2026-09-17；未实施。
- 决策：保存理解结果、镜头清单、商品参考、生成候选和合成参数；原片编辑和一键复刻作为可选执行方式。
- 理由：电商可用性取决于商品真实性、字幕和卖点，单次模型成功不能证明完整交付。
- 后果：多一道分镜审核，但能定位是理解、图片、视频还是合成出错，也便于替换供应商和核算成本。
