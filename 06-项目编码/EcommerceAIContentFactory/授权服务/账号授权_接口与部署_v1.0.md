# 独立账号设备授权服务 v1.0

## 结论与范围

Node 24.19.0 + 已有 Express 5.2.1/Zod 4.6.5 + 内置 SQLite，不新增依赖，不挂接或启动主应用。
账号只能绑定一个 `machineId + devicePublicKey` 组合。首次成功登录原子绑定；账号只能由管理员 CLI 创建。
无注册、客户端解绑、HTTP 管理入口。管理员吊销或换机即时阻断旧授权的在线续期。

最终长期续期方案：`POST /v1/leases/refresh {lease,challengeId,signature}`。
历史 lease 可以过期，但签名、issuer、账号版本、账号状态、公钥与硬件绑定仍必须有效，并且每次有新的设备签名挑战。
没有 refreshToken、refresh_credentials 表或 30 天期限。关软件后可保存历史 lease，启动先在线恢复。
客户端必须通过固定 pin 的签名公钥验签，不以在线发现的公钥自动替换本地信任。

交付范围为可部署代码、部署操作说明和本机隔离测试；尚无真实域名，不包含公网部署、TLS 证书签发或真实双电脑验收。

## 客户端接口

所有 POST 使用 UTF-8 `application/json`，请求体不超过 8KB，不接受多余字段、压缩请求体或 URL 参数代替 JSON。
服务端不记录请求体、密码、签名、租约或原始异常。响应统一禁缓存。

| 字段 | 定义 |
|---|---|
| username | 大小写敏感，3-64 个 ASCII 字符；首字符为字母或数字，后续允许字母、数字、下划线、点、短横线。不自动 trim/归一化 |
| password | 12-128 字符，UTF-8 不超过 256 字节，无控制字符；不自动 trim |
| machineId | Windows 硬件摘要，SHA-256 的 64 个小写 hex 字符 |
| devicePublicKey | Ed25519 公钥，SPKI DER/base64url，无 padding，59 字符 |
| deviceId | 服务端计算的 SHA-256(SPKI DER)/base64url，43 字符；不是硬件摘要 |
| signature | Ed25519 对 signingInput 原字符串 UTF-8 字节签名，base64url，无 padding，86 字符 |
| challengeId | 随机 24 字节/base64url，32 字符 |
| expiresAt、refreshAfter | Unix 毫秒时间戳；挑战默认 60 秒，租约默认 300 秒 |

### 1. 获取挑战

`POST /v1/challenges`

请求：

```json
{
  "username": "tester",
  "machineId": "64位小写hex硬件摘要",
  "devicePublicKey": "SPKI DER的base64url",
  "purpose": "login"
}
```

`purpose` 只接受 `login` 或 `refresh`。成功 HTTP 201：

```json
{"challengeId":"随机ID","signingInput":"原样签名的字符串","expiresAt":1790000000000}
```

示例中的说明文字和时间不是可直接使用的测试凭据。客户端不得重排、trim 或自行重建 `signingInput`。
签名文本包含版本、issuer、用途、账号、公钥摘要、硬件摘要、挑战 ID、随机 nonce 和截止时间，以 LF 分隔。
客户端应校验响应类型和长度，使用设备私钥签名。挑战仅能用于相应用途和账号；消费时检查有效期。
成功、错误密码、错误设备签名、绑定冲突均消费挑战；已消费挑战不可复用。
格式不合法、限流或签名无效的 lease 在进入消费事务前被拒绝，重试仍建议获取新挑战。

### 2. 登录并首次绑定

`POST /v1/login`

```json
{"username":"tester","password":"仅通过HTTPS提交的密码","challengeId":"挑战ID","signature":"base64url签名"}
```

`machineId/devicePublicKey` 已在挑战中绑定，不在登录请求重复提交。
成功 HTTP 200：

```json
{"lease":"header.payload.signature","expiresAt":1790000300000,"refreshAfter":1790000150000,"deviceId":"公钥摘要","machineId":"硬件摘要"}
```

### 3. 无密码在线续期

先取 `purpose: "refresh"` 的挑战，并以同一设备密钥签名。

`POST /v1/leases/refresh`

```json
{"lease":"当前或历史的已签名租约","challengeId":"全新的挑战ID","signature":"base64url签名"}
```

返回同登录成功结构。默认在 `refreshAfter`（签发后 150 秒）续期；客户端可在新任务提交前强制续期。
租约过期本身不阻断续期，但管理员吊销、换机、账户不存在、版本不匹配或设备签名失败会阻断。
退出应用或清理本地文件不会解除服务端绑定。同机可以并行运行客户端进程，约束对象为设备，不是进程。

### 4. 错误

```json
{"error":{"code":"DEVICE_ALREADY_BOUND","message":"账号已绑定其他设备，请联系管理员换机"}}
```

| HTTP | code | 客户端处理 |
|---|---|---|
| 400 | INVALID_INPUT / INVALID_DEVICE_KEY | 修正字段、类型或公钥格式 |
| 401 | INVALID_CREDENTIALS | 账号或密码错误；不存在账号同样响应 |
| 401 | CHALLENGE_INVALID / CHALLENGE_EXPIRED | 取新挑战，不重放旧请求；管理员操作也会清理待用挑战 |
| 401 | DEVICE_PROOF_INVALID | 检查原文签名和本机密钥 |
| 401 | INVALID_LEASE | 固定 pin、签名或声明校验失败，停止提交 |
| 403 | ACCOUNT_REVOKED | 账号吊销或版本变更，联系管理员 |
| 403 | HTTPS_REQUIRED / LOOPBACK_ONLY | 修正入口与代理配置 |
| 409 | DEVICE_ALREADY_BOUND | 不允许切换设备，申请管理员换机 |
| 413 / 415 | PAYLOAD_TOO_LARGE / JSON_REQUIRED | 修正请求体及 Content-Type |
| 429 | RATE_LIMITED | 按 Retry-After 秒数退避；不放行新任务 |
| 503 | SERVER_BUSY | 并发密码计算上限或挑战容量限制，退避重试 |
| 500 | INTERNAL_ERROR | 不携带底层异常，停止提交并由管理员排查 |

`GET /.well-known/jwks.json` 返回 `{keys:[Ed25519公钥JWK]}`，仅用于部署核对。不得以该接口响应自动替换客户端 pin。

## 租约与纯协议模块

`协议.mjs` 只依赖 `node:crypto` 和 Zod，不依赖数据库、Express、文件系统、环境变量或服务端应用。

```js
import { verifyLease } from '../授权服务/协议.mjs';

const claims = verifyLease(lease, {
  publicKey: pinnedPublicPem, // 固定部署公钥 PEM 或 Node 公钥 KeyObject
  issuer: configuredOrigin, // 精确 origin，不带末尾斜杠
  deviceId: localPublicKeySha256Base64url,
  machineId: localHardwareSha256Hex,
  now: Date.now(),
  allowExpired: false,
});
```

`kid` 可选，从固定公钥的 SPKI DER/SHA-256/base64url 自动推导；传入 kid 时须与 pin 一致。
header 必须是 `{alg:"EdDSA",typ:"JWT",kid}`，拒绝算法替换、额外 header 和非规范编码。
claims 为 `iss,aud,sub,username,account,deviceId,machineId,ver,jti,iat,nbf,exp,expiresAt,refreshAfter`。
`aud=ecommerce-ai-content-factory`，`account=username`，`iat/nbf/exp` 为秒，`expiresAt/refreshAfter` 为毫秒。
租约最长 300 秒，不给时钟宽限。验签异常携带 `code/status`；过期为 `LEASE_EXPIRED`，本机绑定不符为 `DEVICE_MISMATCH`。

`allowExpired:true` 只跳过过期判断，不跳过 pin、签名、issuer、设备、未来签发时间或时间字段一致性校验。
客户端仅在磁盘恢复时使用；历史 lease 不能直接用于业务访问，启动后必须在线续期成功。
服务端续期除协议验签外，在 SQLite 事务中额外校验账号状态、版本和已绑定设备。
服务端调用协议函数时可以省略本机期望摘要，因为后续事务按数据库比对；客户端必须提供摘要或另行执行同等校验。

## 绑定与安全边界

- SQLite `BEGIN IMMEDIATE` 将挑战消费、状态检查、唯一设备绑定和签发放在同一写事务，多个进程共享同一磁盘数据库也只能有一个首次绑定获胜。
- 密码存储使用独立 16 字节随机盐的 scrypt（N=32768,r=8,p=1，32 字节输出）；未知账号同样计算，恒定时间比较；每实例最多 4 个并发密码计算。
- 默认每分钟 IP 总请求 240 次；每账号密码登录 10 次、挑战 60 次、续期 60 次，分别计费；限流数据写 SQLite，跨实例共享，重启不重置当前窗口。
- 挑战全局最多 10000 条，限流桶最多 20000 条，按过期清理，避免无界增长。
- 管理员换机直接绑定申请文件中的硬件和公钥、递增版本并启用账号，没有客户端可争抢的空绑定窗口。吊销保留原绑定、递增版本并停用账号。
- 管理操作审计仅保存动作、账号内部 ID 和时间，不保存密码、租约或设备私钥。
- 硬件摘要由客户端声明。服务端能拒绝不同摘要，无法独立证明其真实硬件来源；若攻击者同时复制可用私钥并伪造相同摘要，纯软件协议无法区分。DPAPI CurrentUser 降低跨 Windows 账户复制风险，非远程硬件证明。
- 单纯离线验签无法得知刚发生的吊销，最长剩余窗口为 5 分钟。工作台新提交前强制在线续期可关闭该窗口；已提交上游任务允许收尾，由工作台控制。
- 禁止把 `allowExpired:true` 用于业务放行。签名密钥更换后旧租约失效，必须先更新客户端固定 pin 并重新登录；当前不实现自动密钥轮换。

## 管理员与启动

在项目根目录运行。运行数据建议放在源码和 Web 根目录之外，只给授权服务账户及管理员读写权限。
下面的 `C:/ProgramData/电商授权中心` 必须不存在；初始化不会覆盖已有目录或密钥。

```powershell
node 授权服务/管理员.mjs 初始化 C:/ProgramData/电商授权中心
node 授权服务/管理员.mjs 创建 C:/ProgramData/电商授权中心/账号.sqlite tester
```

创建账号在交互式终端输入两次隐藏密码。密码不作为命令参数、不读取环境密码、不提供公开注册。
初始化生成 `签名私钥.pem`、`签名公钥.pem`、`账号.sqlite`。私钥仅保留在授权中心；公钥通过可信发布流程 pin 到客户端。
Windows 需用 NTFS ACL 限制运行目录，Node 的 mode 不能替代 Windows ACL；Linux 可使用专用用户和目录 0700/私钥 0600。

```powershell
node 授权服务/管理员.mjs 吊销 C:/ProgramData/电商授权中心/账号.sqlite tester
node 授权服务/管理员.mjs 换机 C:/ProgramData/电商授权中心/账号.sqlite tester ./设备换机申请.json
```

换机申请必须精确包含 `{version:1,machineId:"64hex",devicePublicKey:"SPKI DER/base64url"}`。
另一种形式为 `换机 <数据库> <账号> <64hex硬件摘要> <设备公钥base64url文本文件>`。
CLI 管理已有同一份数据库；不要复制数据库到每个实例，否则不再是全局唯一绑定。SQLite 文件必须位于本机磁盘，不使用网络共享盘。

本机验收：

```powershell
$env:AUTH_DATABASE_PATH = 'C:/ProgramData/电商授权中心/账号.sqlite'
$env:AUTH_SIGNING_KEY_FILE = 'C:/ProgramData/电商授权中心/签名私钥.pem'
$env:AUTH_PORT = '4319'
node 授权服务/启动.mjs --本机验收
```

仅监听 `127.0.0.1:4319`，默认 issuer 为该 origin。端口被占用会失败退出，不停止或接管已有服务；换端口需同步修改客户端 URL。
本机验收也要求完整密码、设备签名和绑定流程，只放宽 loopback HTTP 传输，不绕过授权。

## 生产部署准备

需要真实域名、HTTPS 证书及同机反向代理后再部署。启动默认生产模式，不依赖 NODE_ENV 切换，也不接受公网明文入口。

```powershell
$env:AUTH_ISSUER = 'https://license.example.com'
$env:AUTH_TRUSTED_PROXY_IPS = '127.0.0.1'
node 授权服务/启动.mjs
```

示例域名仅为说明，须替换实际 origin。其余数据库、签名密钥路径和端口沿用上面的配置。
代理 HTTPS upstream 指向 `http://127.0.0.1:4319`，必须覆盖而非透传来自客户端的转发头：

```nginx
location / {
    proxy_pass http://127.0.0.1:4319;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto https;
    proxy_set_header X-Forwarded-For $remote_addr;
    client_max_body_size 8k;
    proxy_read_timeout 15s;
}
```

该 location 仅放在配置有效证书的 HTTPS server 中；公网 HTTP server 只返回 403，不转发带密码的 HTTP 请求。
禁止记录 request_body、Authorization、Cookie 或 token；访问日志不要写 query string。应用自身不输出请求日志。
网络侧不暴露后端端口，仅允许可信同机代理。启动入口只信任显式配置的同机 IP，Express 不使用 `trust proxy=true`。
运维需持久保管数据库与签名私钥，使用 SQLite online backup 或停服备份，不单独复制正在写入的主文件而漏掉 WAL。

## 执行与验收

```powershell
node --test 测试/账号授权.test.mjs 测试/工作台授权.test.mjs
Get-ChildItem 授权服务 -Filter *.mjs | ForEach-Object { node --check $_.FullName }
```

测试使用临时库、运行时新生成的密钥、随机 loopback 端口和两个模拟设备身份；结束后关闭全部测试服务器并清理临时目录。
测试没有访问真实授权数据库、已有私钥或外部公网，也不改变运行中的主应用。
客户端接入验证包括 fail-closed、配置与授权入口可用、复制记录拒绝、重启恢复、断网拒绝新提交及吊销后阻断新增任务。
最新实测结果见同目录 `账号授权_验收记录_v1.0.md`。
