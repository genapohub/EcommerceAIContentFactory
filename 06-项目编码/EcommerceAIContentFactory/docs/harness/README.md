# docs/harness · Harness 方法论速览

本目录是 `ai-harness-kit` 的**可选方法论参考**，用于理解「为什么需要治理层」以及本 kit 各文件的分工。不需要可直接删除整个 `docs/`，不影响治理壳运行。

## 一、Harness 是什么

Harness 不是模型能力，而是把 AI 编程**安全、可控、可观测、可回滚**地跑起来的工程约束层。它解决的是「AI 产出怎么管」，不是「AI 能不能写」。

## 二、五层架构

| 层 | 职责 | 本 kit 对应物 |
|---|---|---|
| L1 基础设施 | 模型与运行环境 | 你选用的模型 / 本地或云端推理 |
| L2 执行层 | 可执行的角色知识 + 编排 | `skills/` 角色技能 + 调度器 |
| L3 约束层 | 行为规范与红线 | `AGENTS.md` + `SECURITY.md` |
| L4 反馈层 | 产出校验与状态持久化 | `evals/` + `project-tracker.md` |
| L5 观测层 | trace / log / metrics | 暂不内置（团队规模到一定程度再补） |

## 三、治理三件套

| 文件 | 作用 |
|---|---|
| `AGENTS.md` | AI 行为宪法：角色、工作流、红线、review |
| `project-tracker.md` | 项目状态单一事实源：WIP、风险、决策、交接 |
| `SECURITY.md` | 安全子法：密钥、脱敏、模型路由、事故响应 |

## 四、取舍原则（通用）

1. **自主度**：默认停在「对话 + 协作」，不轻易上「全自主代理」。
2. **红线**：敏感数据不外发公网模型；AI 不直接推 main；跳过扫描不 merge。
3. **节奏**：先骨架再追加细节；每次稳定变更更新 `AGENTS.md` 版本段并打 `harness-vX.Y` tag。

## 五、怎么用本目录

- 只想拿到治理骨架：不必读，直接把本仓库克隆成项目根目录即可。
- 想理解设计取舍：读本文件即可，配合根目录三件套对照理解。

> 维护者的深度调研与实战笔记保留在本地，不随模板分发；本目录对外只保留这一份通用速览。
